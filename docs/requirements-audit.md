## Таблиця оцінювання

У PDF: технічна якість — до 20 балів, захист — до 15, записка — до 15; це не автоматично присвоєні бали. Спеціальні ваги дисципліни мають пріоритет над загальною командною рубрикою.

- A: README і журнал рішень є. Щотижнева історія, issue, три своєчасні етапи та закриття зауважень не доведені.
- B: код, перевірки й документація наявні. Узгоджені строки, формальне закріплення внеску та зовнішні review не підтверджені.
- C: актуальні приймальні тести, обробка помилок і статичний аналіз пройдені. Покриття рядків 43,51% тільки для налаштованого набору; максимум за coverage/CI не досягнуто. БД у активному UI немає; оцінюється робота з файлами.
- E: запуск описаний, але особисті відповіді та зміни на захисті ще не оцінені.
- F: записку оновлено; обов’язкові персональні поля й Git URL залишаються незаповненими.

META-USAGE оновлено. Неможливо чесно підтвердити «всі вимоги на 100%» або гарантувати оцінку до заповнення полів, надання процесних доказів та захисту. Заднім числом коміти, review чи дедлайни не створювалися.

Додаткове уточнення викладача про 3 переходи: /login → /analyze → /diseases → /diseases/:id. Це вимога зі слів користувача, не текст PDF. Історія, справжня авторизація та ML не додаються: користувач явно обрав лише фронтенд.
