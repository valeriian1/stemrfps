# Рішення щодо реалізації

| Проблема | Рішення |
| --- | --- |
| Початковий обсяг завеликий для фронтендного проєкту | Залишити аналіз фото, довідник і форми входу та реєстрації |
| Модель комп’ютерного зору потребує окремої розробки | Використати асинхронний сервіс із демонстраційним результатом |
| Поля, сезони й ролі ускладнюють інтерфейс | Прибрати ці екрани та пов’язаний код |
| Історія не входить до поточного сценарію | Видалити сховище; залишити іконку без дії |
| Для демонстрації форм не потрібен сервер | Перевіряти введення локально, не зберігати паролі та не створювати сесію |
| Великі фото витрачають пам’ять | Перевіряти файл і створювати JPEG-копію до 1600 px на довгій стороні |
| Старий запит може завершитися після вибору іншого фото | Скасовувати запит і перевіряти номер операції перед оновленням стану |
| Зайві бібліотеки ускладнюють підтримку | Використати звичайні React-форми та CSS |
| Текстовий результат важко переглядати | Показувати фото, опис, кільцеву діаграму та сегментовану шкалу |
| Довгі статті перевантажують каталог | Залишити короткі картки, повний опис винести на окрему сторінку |
| Бічна панель займає місце на телефоні | На ширині до 600 px використовувати бургер зі спливним меню |
| Фотографії сповільнюють довідник | Додати WebP-мініатюри, srcset і відкладене завантаження |
| Динамічна компіляція Zod порушує CSP | Увімкнути jitless без послаблення політики безпеки |
| Зміни інтерфейсу можуть порушити сценарії | Перевіряти їх у Playwright, логіку сервісів у Vitest |
