# Coursework

Фронтенд вебсистеми для аналізу фотографій пшениці та перегляду довідника хвороб. Реалізовано форми входу й реєстрації, завантаження фото, дашборд із демонстраційними показниками, експорт через друк браузера та довідник десяти хвороб із пошуком.

## Технології

React, TypeScript, Vite, React Router і Zod. Оформлення написано власним CSS із Grid, Flexbox та медіазапитами. Шрифт Geist і фотографії завантажуються локально.

## Запуск

Потрібні Git, Node.js 22.14 або новіший та npm.

```sh
git clone https://github.com/valeriian1/stemrfps.git
cd stemrfps
npm ci
npm run dev
```

Відкрийте адресу, яку покаже Vite в терміналі. Сервер працює, поки запущена команда; для зупинки натисніть Ctrl+C.

Якщо проєкт уже завантажено, відкрийте термінал у його папці, де знаходиться `package.json`, і виконайте `npm ci` та `npm run dev`.

## Можливості

- Вхід і реєстрація з перевіркою полів. Логін містить від 3 до 64 символів, пароль від 8 до 128. Реєстрація перевіряє збіг паролів.
- Вибір JPEG, PNG або WebP через пунктирну область. Ліміт файла становить 10 × 1024 × 1024 байтів; у підказці інтерфейсу він позначений як 10 МБ. Перевіряються формат, розмір і можливість прочитати зображення.
- Попередній перегляд, заміна та видалення фото. Під час аналізу доступне скасування.
- Дашборд із фотографією, описом ймовірної хвороби, кільцевою діаграмою площі ураження та сегментованою шкалою класифікації.
- Повернення зі статті або довідника до результату зі збереженим фото. Стан зберігається під час переходів усередині сайту та очищується після перезавантаження вкладки, виходу або початку нового аналізу.
- Кнопка «Експортувати звіт» відкриває друк браузера. У вікні друку можна вибрати збереження у PDF. Окремі стилі прибирають навігацію та оформлюють звіт для друку.
- Довідник десяти хвороб із пошуком за назвою та симптомами. Статті містять фото з лупою для курсора, опис, розгортані розділи й джерела.
- Адаптивні картки та дашборд. На ширині до 600 px бічну панель замінює верхня панель із мобільним меню.

## Межі прототипу

Аналіз імітується локально протягом приблизно двох секунд. Основний сценарій показує буру іржу, площу ураження 28% та показники класифікації 76%, 16% і 8%. Ці значення задані для демонстрації та не обчислюються з фотографії. Фото обробляється у браузері без надсилання на сервер.

Форми входу й реєстрації демонструють інтерфейс: облікові записи та сесії не створюються, маршрути доступні напряму. Сервер, модель комп’ютерного зору, постійна історія аналізів і режим PWA не реалізовані. Іконка історії поки не виконує дій.

## Збірка та перевірки

Усі команди виконуються з папки, що містить `package.json`.

```sh
npm run lint
npm run build
npm run test:coverage
npx playwright install chromium firefox webkit
npm run test:e2e
```

`npm run build` перевіряє TypeScript і створює готову збірку в `dist`. Браузерні тести використовують цю збірку, тому перед ними потрібно виконати збірку. Playwright сам запускає сервер попереднього перегляду на порту 5181; цей порт має бути вільним.

Набір Vitest містить 34 модульні тести. Покриття вимірюється для `src/domain/wheat.ts` і сервісів, без React-компонентів. Налаштовано мінімальні пороги 80% для інструкцій, гілок, функцій та рядків.

Набір Playwright містить 10 сценаріїв у чотирьох конфігураціях: Chromium, Firefox, WebKit і Mobile Chrome. Повний запуск передбачає 40 перевірок. Результат конкретного запуску показано в терміналі та HTML-звіті:

```sh
npx playwright show-report
```

Звіт покриття доступний локально в `coverage/index.html`. Згенеровані звіти тестування та матеріали `output` не додаються до Git.

Автоматичні перевірки налаштовано в [GitHub Actions](https://github.com/valeriian1/stemrfps/actions). Там можна переглянути статус запусків і завантажити їхні артефакти. Конфігурація міститься у [.github/workflows/verify.yml](.github/workflows/verify.yml).

## Структура

```text
src/
  main.tsx         Запуск React
  App.tsx          Маршрути сторінок
  index.css        Оформлення, адаптивність і друк
  pages/           Вхід, аналіз, довідник і стаття
  components/      Каркас, навігація, дашборд і спільний стан
  services/        Підготовка фото та імітація аналізу
  domain/          Типи й перевірка даних результату
  data/            Описи хвороб і дані фотографій
public/            Зображення, шрифт та статичні файли
tests/             Браузерні сценарії Playwright
docs/diagrams/     Редаговані діаграми draw.io
```

Автори, ліцензії та посилання на оригінали фотографій наведені в [public/reference/ATTRIBUTION.md](public/reference/ATTRIBUTION.md). Мініатюри каталогу підготовлено у WebP з кількома розмірами. Політика CSP обмежує джерела ресурсів і забороняє `eval`.

## Розгортання

Після `npm run build` розмістіть вміст `dist` на статичному хостингу. Налаштуйте повернення `index.html` для маршрутів застосунку, щоб пряме відкриття `/analyze` і `/diseases` працювало. Для локального перегляду готової збірки використовуйте `npm run preview`.

Для підключення реального аналізу потрібно замінити демонстраційну реалізацію `analyzePhoto` зверненням до API та перевіряти отримані дані за схемою результату.
